# Storing and scanning vectors in the store's SQLite — measured

2026-10-01/02, for [phase 5](../plans/phase-5.md). Scripts and raw results in
[`bench/vectors/`](../../../bench/vectors/): `bench.mjs` (run by `run-all.sh`, `run-1m-f32.sh`),
`results.jsonl`, `results-1m-f32.jsonl`; the extension checks are `load-*.mjs` and `maps.mjs`, the
built-in build `core_init.c` and `builtin-test.mjs`. Synthetic random unit vectors only.

Node 24.19.0 and 22.23.2 (official builds), Bun 1.3.14, Alpine `nodejs` 24.18.1 in Docker; Ryzen AI 9 HX
470, 30 GB. sqlite-vec 0.1.9 (latest stable, 2026-03-31; 0.1.10-alpha.4 on 2026-05-18; the README still says
"pre-v1, so expect breaking changes").

## Loading sqlite-vec

- **Official Node 24 and 22**: works with `new DatabaseSync(path, { allowExtension: true })` and
  `loadExtension(getLoadablePath())`. Without `allowExtension`: `ERR_INVALID_STATE extension loading is not
  allowed`. Node binds a JS number as REAL, so a `vec0` rowid must be a BigInt (`Only integers are allows for
  primary key values`); Bun accepts a number. `LD_LIBRARY_PATH` changes nothing: SQLite is built in.
- **Bun on Linux**: `loadExtension` works on its built-in SQLite 3.53.0. `Database.setCustomSQLite` is a
  no-op outside macOS (the version stays 3.53.0).
- **Alpine (musl)**: the npm prebuilt `vec0.so` is built for glibc — `Error relocating vec0.so:
  __memcpy_chk: symbol not found`, which Node reports as a misleading "No such file". npm has no musl
  package. The amalgamation builds on musl with `-Du_int8_t=uint8_t -Du_int16_t=uint16_t
  -Du_int64_t=uint64_t`, and only under the file name `vec0.so` (SQLite derives the entry point from it).
- **Compiled into our SQLite** (`packages/sqlite/build.sh`'s flags plus `-DSQLITE_CORE
  -DSQLITE_VEC_STATIC` and an auto-extension hook): the musl library grew from 1,690,472 to 1,814,304 bytes
  and `vec0` worked with no `allowExtension`. That reaches only Bun on macOS and a distro Node restarted onto
  our library; official Node and Bun on Linux never load it.
- **Not measured**: macOS, linux-arm64.

## Speed and size

One top-10 query. Insert is one transaction. "First query" opens a fresh connection and streams every row
with a dot product — from the page cache (the files were on tmpfs), not a cold disk. "Load" reads all rows
into one array; "in memory" is the median of 5 queries over it, which needs a process that stays up.
`vec0` peak memory stayed at 60–101 MB.
